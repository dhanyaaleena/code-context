How it works, and why it's built this way.

An editor extension that reconstructs how an unfamiliar function fits into a system — its steps, the routes and jobs that reach it, its callers, its history — from source, Git and framework routing. A language model is used for one thing only: turning those facts into sentences.

For engineers reviewing the design. Six pages: principles, the component map, the index, the context pipeline, the AI layer, and the runtime lifecycle with known limits.

Design principles

Facts first, words second

Every design decision below follows from one split: deterministic analysis decides what is true; the model only decides how to say it. A wrong sentence can be traced to a wrong fact, and a wrong fact to a line of code.

01
The model translates; it never discovers

Routes, steps, callers and commits are all computed before any model is called. It receives a numbered evidence bundle and is told to use nothing else. Turn AI off and you lose sentences, not facts.

02
Grounded by shape, not by prompt

Instructions are necessary but not sufficient. Cited evidence ids are checked against the ids actually issued; each plain-language step must name the step it translates; a reason is labelled inferred unless a commit stated it.

03
Confidence is structural

Every caller edge is resolved (same file, or imported) or heuristic (name match only), and is drawn accordingly. The tool is designed to be visibly unsure rather than confidently wrong.

04
Never block on the model

The computed panel renders immediately; the narration folds in when it arrives, and a cache hit shows no loading state at all.

05
The reader decides when to spend

Changed code is flagged stale, never re-analysed in the background. Agents write in bursts; describing each one would bill for half-written code nobody asked about.

06
Local by default

Indexing and analysis run against the working tree and Git. Nothing leaves the machine until AI is switched on, and then only a bounded bundle for the one function opened.

The index

Index once, then touch only what changed

A single panel open performs dozens of "who mentions this name?" lookups — for callers, for the transitive hop, for walking up to entry points. The index exists to make each of those a map read.

Build once

On activation, in the background: every .py file (capped by maxFiles), its symbols, its identifiers, and the workspace's entry points.

Update one file

A save or a write from outside the editor re-reads that file, swaps its slice of the name index, and rescans entry points. The rest is untouched.

Persist by commit

Saved to extension storage with the HEAD commit. A cold start asks Git what changed since, and re-reads only that.

Cold start

Only file text is cached; symbols and entry points are always recomputed, so a change to the scanner can never be masked by stale derived data. Caches above 24 MB are not written — a repository that size is cheaper to rescan than to serialise.

The inverted name index
// identifier → files that mention it
"get_current_user" → { admin/routes.py,
                        auth/deps.py,
                        reports/export.py }
"compute_ap_signal" → { scoring/ap.py,
                         scoring/jobs.py }

Caller search used to be a regex sweep of every file, for every lookup. Now the index returns the handful of files that mention the name, and only those are scanned for real uses.

Measured on a synthetic 400-file, 4.9 MB corpus: 16 ms → 0.007 ms per lookup. More importantly, cost now grows with how often a name is used, not with the size of the repository.

Building a context

Eight stages, all deterministic

From the function at the cursor to a ContextResponse. Memoised per document version, so the CodeLens, the hover and the panel share one computation.

1Symbol

Find the function enclosing the cursor and its full body — from the language pack (def and indentation for Python, func and brace matching for Go) or, for any other language, from the language server's document symbols.

2Steps

Read the body into typed steps, by the pack's rules. Python: an except tail folds into one step, Depends(get_db) becomes a requirement. Go: an if err != nil check folds into the call it guards; c.JSON(404, …) reads as "answers 404".

3Callers

The language server's references first — type-aware, so every edge is confirmed. Without one, the name index and the pack's rules: an import for Python; for Go, same package or a pkg.Name through an import, and lowercase names never cross packages.

4Callees

The language server's call hierarchy first; otherwise names called from the body, resolved to definitions in the repository. Anything outside it is marked external with the library it comes from.

5Entry points

Python: FastAPI, Flask, Celery, APScheduler, Click, Typer, Django signals. Go: net/http, Gin, Echo, Chi, Gorilla mux and Fiber with group prefixes, Cobra, cron, gRPC, main() — traced from where a route is registered back to the handler it names. Other functions inherit the routes of the handlers above them.

6Feature

The directory it belongs to, skipping containers like apps/ and src/, plus files that keep being committed alongside it — ignoring sweeping commits of more than 20 files and requiring at least two co-occurrences.

7History

git log -L :symbol:file — genuinely symbol-scoped — with commit bodies, trailers stripped. The commit that introduced the symbol is always kept, however old, because it is the only one that says why it exists.

8Tests & freshness

Test files that reference it, by path convention; the commit the answer reflects; whether the buffer has unsaved edits.

Where resolution is weakest

Without a language server, callers are matched by name, and a Go method call can't be tied to its type — those edges are marked guesses. Neither method sees getattr dispatch or reflection, which is why "no callers" is never presented as "unused".

The AI layer

One call, fenced in

A single structured request per function. The model sees a numbered bundle of computed facts and returns a fixed schema; everything it returns is checked before it reaches the screen.

The evidence bundle
SYMBOL: get_current_user()
SOURCE: …first 80 lines…
HOW THE OUTSIDE WORLD REACHES IT:
  [entry:0] http — GET /api/v1/admin/stats
WHAT IT DOES, IN ORDER:
  [step:0] call — verify id token
  [step:1] read — looks up user id
  [step:2] error — fails with 401 when …
USED BY:  [caller:0] routes.admin_stats (resolved)
WHY IT WAS ADDED:
  [commit:827fb4e] Add Firebase admin auth
    reason given: …commit body…
CHANGED SINCE:  [commit:2cd9272] …
TESTS: 0 test file(s) reference it.

Checked after it returns

Evidence ids must be real

Cited ids are filtered to those actually issued, capped at five. Models otherwise cite section headings.

Steps are placed by number

Each line names its step; 0- or 1-based numbering is detected. A miscount costs one line, which falls back to the computed label.

"Stated" has to be earned

With no commits in the bundle, originBasis is forced to inferred whatever the model says.

Shape is never trusted

Every provider gets the same schema, and every reply is shape-checked before use.

Caching & cost

Keyed by model + SHA-256 of the bundle. The bundle has no line numbers, so edits elsewhere in the file replay for free. Re-analyse bypasses the read and overwrites the entry. One retry on 429/503. Roughly 2–3k tokens in, a few hundred out — well under a cent on Haiku.

Code Context · Architecture6
Runtime

Open, render, narrate — then watch

Focus

The panel tracks {file, qualified name, line, source}. By name, because an edit above the function moves every line; the line only breaks ties and follows a rename in place.

Staleness

Buffer edits and on-disk writes both trigger a 400 ms check: re-find the function, compare its source to the snapshot. Edits elsewhere don't count; undo clears the flag. It never calls the model.

Cursor-follow

The panel follows clicks, arrow keys and go-to-definition. Selection moves caused by an edit carry no kind and are ignored, so an agent dragging the cursor doesn't re-analyse.

Keeping the index current

A file watcher catches writes from Claude Code, Git or any other tool; saves update one file. Both refresh CodeLens counts.
